# CURRENT — CodeForge 개선 계획

2026-11-05 · 브랜치 `docs/agentops-platform-plan` · 문서 준비 기준 `388107defbca80cef612e14716ea2dc0c7242cb0`.

전체 목표는 웹/모바일의 쉬운 채팅 진입점과 개발자 TUI·편리한 workspace가 같은 Core의 Work·정책·증거·승인·복구·scoped memory를 사용하는 플랫폼이다. 초기 controlled OMP fork와 기존 terminal 기반을 재사용하고 upstream은 검증 후 선택 반입한다. Tern은 선택 host이며 필수 tenant sandbox가 아니다. 비개발자만을 대상으로 좁히지 않는다.

## 상태와 이번 승인 범위

기획 통합안과 그 원문에 기록된 실제 Claude 독립 검토·개인 Codex 대조/감사는 지정 자료 범위의 계획 검수다. 제품 구현·보안/격리 실증·시장 검증·출시 완료가 아니다. 이번 후보 준비에서는 추가 모델·agent, 앱·브라우저·실행기 smoke, 테스트·formatter를 실행하지 않는다.

화면부터 설계하자는 방향은 유지한다. 첫 시안은 사용자가 ‘완전 클로드 디자인 그 자체’라고 거절하고 ‘그냥 멈춰’라고 중단했다. 승인·완료된 성과가 아니며 디자인은 중단 상태다. **자동 재개 금지.** HTML/CSS/JS·디자인 명세·스크린샷·runner/browser tooling·로컬 로그는 반입하지 않는다.

기존 plugin 수리 track과 새 플랫폼 G0a/G0b/G2/G3/G4 gate는 별도로 유지한다. G0a는 복구 가능한 기준선, G0b는 최소 계약·실증, G2는 단일 runtime·공개 repo의 로컬 흐름과 기본 기억, G3는 실제 두 runtime·두 pack·지원 조합, G4는 원격 모바일·상시 authority/worker의 검증이다. 세부 의존성과 출시 조건은 상세 정본 §8을 따른다.

사용자가 승인한 원격 게시 범위는 이 브랜치의 기획 문서 네 개뿐이다. main·릴리스·제품 배포는 제외한다. 현재는 후보 준비 단계로 commit/push하지 않았다. 후속 신뢰된 기계적 실행기가 공식 guard admit·게시 검사와 기존 Git hooks를 유지해 임시 Git 인덱스로 네 문서만 반영·게시한다. 원격 게시 완료는 실제 commit/push/readback 결과로 별도 확인한다.

root의 사용자 변경·인덱스·기존 worktree 등록은 보존 대상이다. root의 미추적 동명 CURRENT는 읽거나 복제하지 않고 기준 브랜치에 새 진입점을 준비했다. 후보 준비는 제품 레포·설정·`.git`·원문을 수정하지 않는다. 자기 커밋 SHA를 쓰는 amend loop는 만들지 않는다.

- 원문 반입 SHA256: `4285f40f2ac842dbd3f5246456e61d58dfe80ba6e8463592c23515233184f7c7`.
- 최신 상세 정본 SHA256: `4285f40f2ac842dbd3f5246456e61d58dfe80ba6e8463592c23515233184f7c7`. 원문 바이트를 그대로 보존하므로 위와 동일하며 내용 보완은 기존 실행 계획에만 둔다.
- 보완한 기존 실행 계획 SHA256: `02f887b56da1f69354f485766b81be6517de48dae60c6ae3bb775f187084053d`. CURRENT 자신의 SHA와 나머지 후보의 SHA는 별도 manifest/최종 보고로 확인한다.

집에서 필요한 설계 본문 전체는 최신 상세 정본과 위 레포 상대 링크에 있다. 상세 정본 말미의 과거 임시 증거 경로는 당시 검토의 출처 포인터이며, 그 파일 없이도 설계 본문과 기록된 검증 한계는 읽을 수 있다. 리뷰 원문·회사 bundle·headless 이미지/layout·감사 JSON·실행 로그는 이식하지 않았다. 따라서 과거 검토/관찰을 원자료로 재현하거나 독립 감사할 자료까지 함께 보존됐다는 뜻은 아니다. 원문 속 ‘이번’과 ‘정본 승격 아님’ 등은 원문 작성 당시의 상태이며 현재 문서 지위는 이 진입점과 기존 실행 계획이 정한다. 공식 반입 receipt·사용 근거 기록은 후속 guard admit에서 다루며 공개 문서에 복사하지 않는다.

## 미결정과 다음 한 단계

시각 방향·레퍼런스·첫 화면 정보 구조는 미합의다. 제품 이름·저장소/언어·OMP fork 변경 범위·실제 runtime/host 조합, provider별 BYOK/허용 OAuth·local/managed 약관과 원가, 사용자 간 인증·기억·비용 격리 실증, 삭제/backup·유료 반복 사용은 결정 또는 검증 대기다. Paperthin/Hermes는 근거 확인과 선택 평가가 남은 참고 후보이며 필수 의존성·도입 완료가 아니다. 가격·quota·라이선스 조건을 새로 확정하지 않는다.

**다음 세션의 정확한 한 단계:** 이 진입점과 상세 정본을 읽은 뒤 사용자와 CodeForge 고유 시각 방향·레퍼런스·화면 정보 구조를 먼저 맞춘다. 새 화면 구현이나 디자인 제작을 자동으로 재개하지 않는다.
