2026-11-07 · 브랜치 `docs/agentops-platform-plan` · 기획 문서 4개 게시·원격 SHA 일치 확인 기준 `a2ecb128d9928e7645a345f5fccd14a35b1028ee` · 이전 문서 준비 기준 `388107defbca80cef612e14716ea2dc0c7242cb0`.

## 상태와 이번 승인 범위

기획 통합안과 그 원문에 기록된 실제 Claude 독립 검토·개인 Codex 대조/감사는 지정 자료 범위의 계획 검수다. 제품 구현·보안/격리 실증·시장 검증·출시 완료가 아니다. 이번 추가 후보 준비는 문서 두 개의 보완과 Python 문서 smoke에 한정한다. 추가 모델·agent, 앱·브라우저·실행기 smoke, 제품 테스트·formatter를 실행하지 않는다.

단계적으로 구현 계획을 확정하는 첫 실제 결정에서 사용자는 **데스크톱의 ‘작업 진행 중’ 기본 구조로 결과 작업대 중심을 선택했다.** 홈페이지·문서·기타 산출물이 중앙의 주인공이고, 대화는 결과를 지시하는 열고 닫는 보조 영역이다. 작업 탐색은 얇게 두고 질문·변경·검증·승인은 해당 결과와 연결해 접근한다.

첫 요청 순간에는 비개발자의 쉬운 채팅 진입점을 유지한다. 모바일은 채팅을 기본으로 결과·검토로 이동한다. 개발자 TUI는 같은 Work의 의미·상태·행동을 키보드로 제공하며 웹 레이아웃을 복제하지 않는다.

두 번째 실제 선택에서 사용자는 **개발자 TUI와 원격 사용 우선**을 명시적으로 선택했다. 웹·모바일과 결과 작업대 방향은 후속 단계로 유지하며, 화면 디자인·시각 방향 확정을 첫 Core 구현의 선행 조건으로 두지 않는다. 최초 수직 흐름 목표는 **TUI 요청 → 실제 실행 → 검증 → 필요한 승인 → 반영 후 확인(readback) → 원격 접속을 끊었다 다시 연결해 같은 Work 확인**이다. TUI는 authoritative 작업 상태의 소유자가 아니며 화면 단절과 작업 수명을 분리한다. 접속 단절·재접속·취소·복구를 계약에 포함하고, 중단 후 외부 작업을 무조건 재시도·재반영하지 않는다.

초기 원격은 사용자 자신이 관리하는 머신·서버에 SSH로 접속하는 경로를 우선 검토한다. 공개 인터넷용 다중 tenant SaaS·격리 완성을 뜻하지 않는다. 모델 credential은 보호된 실행 환경에 남기고 메신저로 받지 않으며, 모델·계정 silent fallback 금지와 사용자별 격리 원칙을 보존한다.

텔레그램 등은 후속 접점으로 알림·상태조회·간단 요청부터 검토한다. 게시·삭제·비용 발생 승인은 사용자·권한·대상 버전·유효성·중복 방지 경계를 갖춘 뒤 검토하며, 처음부터 원격 shell·포괄 승인 권한을 주지 않는다. 텔레그램 구현·새 bot 생성은 현재 승인 범위가 아니다. 네이티브 데스크톱·모바일 앱은 OS 통합·알림·기기 기능의 실제 필요를 확인한 뒤 선택하며 첫 구현 범위에서 제외한다.

비개발자 시장·쉬운 채팅 방향은 유지한다. 개발자 dogfooding 성공만으로 비개발자 사용성·사업성을 입증했다고 보지 않는다.

이 선택은 **정보 구조 방향만 승인**한 것이다. 색·폰트·세부 레이아웃·구현·실제 prototype은 승인되지 않았다. 첫 시안은 사용자가 ‘완전 클로드 디자인 그 자체’라고 거절하고 ‘그냥 멈춰’라고 중단했다. 여전히 기각·중단 상태이며 재사용하지 않는다. **기각 시안의 자동 재개 금지.** 결과 작업대 선택을 ‘다크 3단 패널이 곧 차별성’이라는 결론으로 바꾸지 않는다. CodeForge의 대장간 메타포와 제품 고유성을 보존한다. HTML/CSS/JS·디자인 명세·스크린샷·runner/browser tooling·로컬 로그는 반입하지 않는다.

기존 plugin 수리 track과 새 플랫폼 G0a/G0b/G2/G3/G4 gate는 별도로 유지한다. G0a는 복구 가능한 기준선, G0b는 최소 계약·실증, G2는 단일 runtime·공개 repo의 로컬 흐름과 기본 기억, G3는 실제 두 runtime·두 pack·지원 조합, G4는 원격 모바일·상시 authority/worker의 검증이다. 세부 의존성과 출시 조건은 상세 정본 §8을 따른다.

기존 기획 문서 네 개는 `a2ecb128d9928e7645a345f5fccd14a35b1028ee`로 게시됐고 실제 원격 readback의 SHA 일치까지 확인됐다. 이전의 ‘commit/push하지 않았다’는 문서 후보 당시 상태이며 현재 게시 상태가 아니다. main·릴리스·제품 배포는 승인 범위에 포함되지 않는다.

이번 선택을 기존 기획 문서 브랜치에 반영하고 commit/push하는 승인은 이미 받았으나, **이번 호출은 추가 문서 후보 두 개의 준비·검증만 수행하며 이번 추가 commit/push는 아직 하지 않았다.** 후속 게시 실행은 공식 guard·게시 검사와 기존 Git hooks를 유지하고, 이 두 후보만 반영한 뒤 실제 게시·원격 readback 결과를 확인한다. 이번 추가 문서를 이미 게시한 것으로 기록하거나 최종 커밋 자신의 SHA를 본문에 넣지 않는다.

root의 사용자 변경·인덱스·기존 worktree 등록은 보존 대상이다. root의 미추적 동명 CURRENT는 읽거나 복제하지 않고 게시 기준 Git 객체에서 문서 후보를 준비했다. 후보 준비는 제품 레포·설정·`.git`·원문을 수정하지 않는다. 자기 커밋 SHA를 쓰는 amend loop는 만들지 않는다.

집에서 필요한 설계 본문 전체는 최신 상세 정본과 위 레포 상대 링크에 있다. 상세 정본 말미의 과거 임시 증거 경로는 당시 검토의 출처 포인터이며, 그 파일 없이도 설계 본문과 기록된 검증 한계는 읽을 수 있다. 리뷰 원문·회사 bundle·headless 이미지/layout·감사 JSON·실행 로그는 이식하지 않았다. 따라서 과거 검토/관찰을 원자료로 재현하거나 독립 감사할 자료까지 함께 보존됐다는 뜻은 아니다. 원문 속 ‘이번’과 ‘정본 승격 아님’ 등은 원문 작성 당시의 상태이며 현재 문서 지위는 이 진입점과 기존 실행 계획이 정한다. 공식 반입 receipt·사용 근거 기록은 후속 guard admit에서 다루며 공개 문서에 복사하지 않는다.

## 미결정과 다음 한 단계

데스크톱 작업 진행 중의 결과 작업대 중심 정보 구조와 개발자 TUI·원격 사용 우선 순서는 확정됐다. 웹의 필수 정보·작업 흐름, 시각 방향·실제 레퍼런스·작은 와이어프레임 검토는 후속 단계에 남기며 바로 할 일로 두지 않는다. 첫 요청의 채팅 진입점·모바일·TUI의 경계는 위 선택 범위를 따른다. 제품 이름·첫 구현 경계(저장소·언어·기술 스택·controlled OMP fork 실제 변경 범위·파일 경로·첫 실행 환경)·최소 실행 계약·실제 runtime/host 조합은 코드 조사 전이므로 미확정이다. provider별 BYOK/허용 OAuth·local/managed 약관과 원가, 사용자 간 인증·기억·비용 격리 실증, 삭제/backup·유료 반복 사용은 결정 또는 검증 대기다. Paperthin/Hermes는 근거 확인과 선택 평가가 남은 참고 후보이며 필수 의존성·도입 완료가 아니다. 가격·quota·라이선스 조건을 새로 확정하지 않는다.

**다음 한 단계:** 실제 OMP에서 재사용할 범위와 첫 실행 환경을 읽기 전용으로 확인하고, G0b 작업 하나의 실행 계약(상태·action·검증·필요한 승인·반영 후 readback·접속 단절/재접속/취소/복구)을 좁힌다. 위 최초 수직 흐름을 목표로 하되 아직 구현·실증 완료가 아니다. 기존 plugin 수리와 새 Core/controlled fork G0b는 분리한다. 새 디자인·프로토타입이나 기각 시안을 자동으로 재개하지 않는다.

이번 문서 검증은 두 후보의 존재·상대 링크의 후보 또는 게시 기준 Git 파일 해결·선택과 미확정의 구별에 한정한다. 외부 링크·앵커 도달은 검증하지 않았다.
