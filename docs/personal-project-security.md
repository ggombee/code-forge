# 개인 프로젝트 자료·전송 규칙

대상은 kkombee·code-forge다. 이 두 프로젝트는 개인 Codex 전용이며 회사 계정으로 자동 전환하지 않는다. 회사 계정·미확인 계정에서는 작업과 외부 전송을 중단한다. 개인 계정 사용과 자료의 사용 권한은 각각 확인한다.

## 접근 범위

승인된 개인 프로젝트와 개발 도구만 사용한다. 회사 저장소·문서·메일·메신저·드라이브·메모리·과거 대화·자격정보·연동 도구를 조회하지 않는다. 상위 폴더 전체 검색이나 링크·worktree·submodule로 허용 범위를 벗어나는 접근을 하지 않는다. 범위를 넓힐 때는 읽기 전에 목적과 대상을 사용자에게 확인한다.

기존 대화에 들어온 회사 관련 맥락까지 규칙으로 지울 수는 없다. 개인 작업은 회사 연동·메모리를 가져오지 않는 새 개인 세션에서 시작하는 것이 원칙이다. 훅은 임의 프로그램 내부의 모든 파일 읽기·전송을 해석하지 못한다. OS 수준 읽기 격리는 별도 환경으로 구성해야 한다.

## 외부에서 작성한 문서 반입

사용자가 별도로 작성한 문서를 지정하면 로컬 검사기만 먼저 읽는다. 원본 회사 자료, 비공개 코드·설계·고객 사례·수치·로그를 이름 변경·번역·요약해 개인 프로젝트로 옮기지 않는다. 회사에서 생각한 아이디어도 독립적으로 쓸 수 있는지, 회사의 권리가 있는지는 별도 확인한다. 자동 검사 통과는 법률·사내 승인이나 권리 귀속의 확인이 아니다.

지원하는 반입 형식은 UTF-8 Markdown·텍스트다. PDF·Word·이미지·압축파일 등은 자동 반입하지 않는다. 검사를 위해 외부 AI에 문서를 보내지 않으며 발견 문자열도 로그에 출력하지 않는다. 사용자가 지정하지 않은 회사 파일이나 주변 폴더를 순회하지 않는다.

반입은 아래 순서로 진행한다.

1. 사용자가 독립 작성한 요약 또는 공개 자료와 출처·사용 근거를 준비한다.
2. 개인 프로젝트 안에서 `inspect`로 지정한 파일만 로컬 검사한다.
3. 사용자가 공개 이용 또는 독립 작성·사용 권한을 확인한다. 불분명하면 반입을 보류한다.
4. 확인한 SHA와 사용 근거를 `admit`에 전달한다. 같은 내용임을 재확인한 뒤 `docs/imported/`로 복사한다.
5. 확인 기록은 개인 로컬 저장소에만 남긴다. 반입 후 내용을 수정하거나 다른 PC로 옮기면 내용·목적지에 맞는 확인을 다시 한다.

```bash
# 경로는 사용자가 지정한 문서로 바꾼다. 이 명령은 프로젝트 폴더 안에서 실행한다.
python3 ~/.config/personal-project-guard/guard.py inspect /개인/검토문서.md

# 위 검사에서 나온 SHA와 실제 확인한 근거를 사용한다.
python3 ~/.config/personal-project-guard/guard.py admit /개인/검토문서.md \
  --destination docs/imported/검토완료-요구사항.md \
  --approved-sha 검사에서_확인한_SHA \
  --source-kind personal-summary \
  --rights-confirmed \
  --rights-note '독립 작성과 사용 권한을 확인한 실제 근거를 기록한다'
```

복사 명령이나 확인 플래그만으로 회사 자료를 개인 자료로 바꾸지 못한다. `docs/imported/` 확인 기록도 사용자의 진술과 내용 일치를 기록할 뿐 법률 판단을 대신하지 않는다. 임의로 다른 경로에 복사하면 그 자료의 출처를 자동 추적할 수 없으므로 동일한 반입 절차를 따른다.

## 전송 전 검증

`pre-push`는 승인된 개인 프로젝트의 목적지·ref·개인 Codex 프로필을 확인한다. Git HTTPS 자격 경로로 GitHub 계정도 확인하며 확인 실패 시 전송을 중단한다. 회사 인증 파일과 비교하지 않는다. 계정 파일이나 환경변수만으로 이미 실행 중인 대화의 인증 주체를 완전히 증명할 수는 없다. 개인 전용 프로필로 시작한 새 세션과 결합해 사용한다.

검사 대상은 전송할 새 커밋·메타데이터·변경 객체다. 중간 커밋에 비밀을 추가했다가 삭제해도 검사한다. 승인되지 않은 원격·ref·삭제·태그, 비밀 형태, 자격 파일, LFS·링크·submodule·해석 불가 파일은 별도 검토 전 차단한다. 새 브랜치는 로컬 정책에 원격 ref와 출발점이 된 정확한 기준 커밋을 함께 등록해야 하며, 해당 커밋 이후의 이력만 검사한다. 최초 전체 이력 감사와 이미 원격에 올라간 자료의 정리는 별도 작업이다.

이 검사기는 표준 라이브러리 기반의 제한된 패턴 검사다. 회사 정보의 의미·저작권·모든 형태의 비밀을 판별하지 못한다. 실제 내부 식별자나 금지 패턴을 공개 저장소에 넣지 않는다. 검사기 누락·오류·용량 초과·계정 미확인·반입 확인 기록 누락은 통과가 아니다. 예외를 자동 생성하거나 훅을 우회하지 않는다.

Git 이외의 API·첨부·배포·웹 업로드도 사용자가 승인한 정확한 전송 내용을 먼저 검토한다. Git 훅은 그런 전송을 검사하지 못한다. Codex 도구 훅은 명시적인 전송 명령·경로를 보조 검사하지만 임의 스크립트나 다른 앱을 통한 우회를 완전히 막지 못한다. 네트워크/파일 격리는 별도 적용한다.

## 사용자 소유 스킬 동기화 예외

개인 계정을 확인하지 못한 상태에서는 원칙적으로 개인 프로젝트 작업을 중단한다. 다만 사용자가 직접 승인한 CodeForge 스킬 동기화는 로컬 정책에 소스와 목적지를 함께 등록한 경우에만 제한적으로 허용한다. 현재 예외 대상은 `handoff`와 `polish-korean` 두 디렉터리다.

예외 상태에서는 등록된 소스 읽기와 대상 디렉터리의 복사·편집·비교·검사만 할 수 있다. 다른 파일 수정, 회사 연동, 네트워크 전송, `git add`·커밋·푸시는 계속 차단한다. 게시가 필요하면 개인 계정을 다시 확인한 새 세션에서 전송 전 검사를 거친다.

## 설치와 확인

공개 가능한 검사 코드는 `scripts/security/`에 둔다. 개인 계정 식별·승인 경로·ref·반입 확인 기록은 Git 밖의 개인 로컬 설정에서 관리한다. 설치기는 변경 파일을 백업하며 다른 프로젝트의 기존 훅 동작을 유지한다. 이 두 프로젝트에 한해 자동 계정 전환·회사 연동 훅을 건너뛴다. Git 계정 확인은 네트워크를 사용하지만 문서·코드를 업로드하지 않는다.

```bash
python3 -B -m unittest discover -s scripts/security -p 'test_*.py'
python3 ~/.config/personal-project-guard/guard.py doctor
python3 ~/.config/personal-project-guard/guard.py staged
```

Codex 훅 설정을 설치한 뒤 새 개인 세션의 `/hooks`에서 실제 정의·신뢰·활성 상태를 확인한다. 설정 파일만 만들었다고 훅이 실행된 것으로 보고하지 않는다. 계정 전환 회피·네트워크 기록 회피를 목적으로 사용하지 않으며 회사 장비의 정책과 모니터링은 바뀌지 않는다.
