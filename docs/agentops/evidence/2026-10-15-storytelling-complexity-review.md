# AgentOps 복잡성·스토리텔링 재검토

> 검토일: 2026-10-15
>
> 대상: CodeForge AgentOps 요약과 메인 설계
>
> 목적: 설계가 실제 문제보다 복잡한지, Obsidian·Hermes·Herdr가 왜 등장하는지, 처음 읽는 사람이 사용 장면을 이해할 수 있는지 재검토

## 검토 조건

이번 판정은 다음 두 근거를 결합했다.

1. 2026-10-14에 완료한 Claude Opus 교차 검토의 반론과 합의
2. 최신 문서에 대한 Codex의 세 라운드 self-debate

새 Claude 실행 결과가 아니다. 다른 독립 모델 검토를 수행할 때 아래 질문과 판정 기준을 재사용할 수 있다.

## Debate Summary

**주제:** 장기 AgentOps 설계가 현재 사용자 문제보다 복잡한가
**모드:** self-debate. 이전 Claude Opus 교차 검토 결과를 반론 기준으로 재사용
**라운드:** 3/3
**참가 관점:** 장기 신뢰 구조 옹호, MVP 단순화 비평, 제품 문서 독자

### 라운드 1 — 구조가 필요한가

장기 구조 옹호 관점은 realm별 데이터 분리, 여러 실행기의 상태 복구, 정확한 승인과 독립 검증을 위해 stable ID, policy, receipt와 realm이 필요하다고 주장했다.

단순화 관점은 이 계약이 필요한 것과 사용자가 첫날부터 모든 구성 요소를 설치해야 하는 것은 다른 문제라고 반박했다. 현재 문서는 장기 내부 계약과 첫 제품의 사용 흐름을 같은 깊이로 보여 주어 실제보다 복잡하게 읽힌다.

**판정:** 신뢰 규칙은 유지하되 첫 화면과 첫 구현에서는 다섯 구성만 보여 준다.

### 라운드 2 — 도구가 모두 필요한가

장기 구조 옹호 관점은 Obsidian이 개인 지식 편집, Hermes가 예약·원격·메신저 실행, Herdr가 현재 터미널 관제에 유용하다고 주장했다.

단순화 관점은 같은 기능을 Markdown 폴더, 운영체제 scheduler, 기본 CLI로 시작할 수 있다고 반박했다. 특정 도구 이름을 코어 구조와 나란히 두면 제품 의존성처럼 보이고, 교체 가능성도 약해진다.

**판정:** 세 도구 모두 선택형 adapter다. Obsidian은 편집 화면, Hermes는 wake·전송 통로, Herdr는 관찰·제어 surface다. 작업·권한·완료는 CodeForge가 관리한다.

### 라운드 3 — 무엇을 먼저 만들 것인가

장기 구조 옹호 관점은 공개 서비스로 확장하려면 protocol, team Hub, 지식 lifecycle과 모델 routing을 미리 고려해야 한다고 주장했다.

단순화 관점은 검증기와 단일 사용자 흐름의 효용을 증명하기 전에 이를 구현하면 이전 Opus 검토가 지적한 Control Plane 과잉설계를 반복한다고 반박했다.

**합의:** 장기 호환성을 깨뜨리는 최소 schema만 먼저 고정하고 기능은 다음 순서로 연다.

1. 작업 1건
2. 실행 adapter 1개
3. 격리된 worktree
4. 저장소의 실제 검사
5. 정적 검토 묶음과 채택·수정·폐기

Hermes, Obsidian 전용 기능, ForgeGlow, 저비용 모델 routing, 팀 Hub는 이 흐름의 효용이 확인된 뒤 추가한다.

## 합의점

- 현재 설계는 **목표 구조로는 타당하지만 한 번에 구현하면 과잉설계**다.
- 복잡성의 가장 큰 원인은 구성 요소 수보다 장기 내부 계약과 첫 사용 흐름이 섞인 문서 구조다.
- 제품 설명은 “사용자의 하루가 어떻게 바뀌는가”에서 시작하고 도구 목록은 그다음에 보여 준다.
- CodeForge가 소유할 것은 작업 기준, 권한, 검증, receipt다.
- Obsidian, Hermes, Herdr, ForgeGlow는 모두 선택형이며 대체 가능해야 한다.
- 사용자 화면에는 내부 상태 이름 전체를 노출하지 않는다.

## 미해결 논점

- 첫 실행 adapter를 Claude와 Codex 중 무엇으로 시작할지
- 최초 제품을 기존 CodeForge v5로 낼지 별도 중립 저장소에서 시작할지
- 개인용 alpha에서 자동 draft PR을 기본 허용할 저장소 범위
- 다른 독립 모델을 사용한 최신 교차 검토

## 권장 결정

**아키텍처 원칙은 유지하고, 제품 설명과 첫 구현을 다섯 구성으로 줄인다.** 요약은 실제 사용 장면과 선택형 도구의 이유를 먼저 보여 주고, 기술 객체·protocol·출시 지표는 메인 설계에 남긴다. Obsidian과 Hermes는 처음부터 설치할 필요가 없으며, 관련 기능이 필요해질 때 연결하는 adapter로 명시한다.
