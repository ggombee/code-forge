# Herdr + OMP + Hermes + Qwen 기반 통합 관제 재검토

- 기준일: 2026-10-14
- 조사 유형: 기술 비교 및 개인 개발자·소규모 팀용 제품 구조 재검토
- 결론 신뢰도: 높음. 로컬 Herdr 0.9.0 명령 출력과 각 프로젝트의 공식 문서·공식 저장소를 기준으로 삼았다.
- 현재 지위: **초기 비교 자료. 최종 제품 구조와 구현 순서는 [`11.codeforge-public-service-architecture-debate.md`](./11.codeforge-public-service-architecture-debate.md), 야간 실행은 [`12.night-runner-reference-audit-and-design.md`](./12.night-runner-reference-audit-and-design.md)를 따른다.** 이 문서의 Hermes·Herdr·OMP 중심 배치는 최종안이 아니다.

## 결론

처음 제안한 독립 Control Core를 처음부터 크게 만들 필요는 없다. 현재 조합은 이미 필요한 기능의 대부분을 나눠 갖고 있다.

- **Hermes Agent**: 사용자와 대화하고 기억하며 일정·메신저·병렬 위임을 담당하는 상위 개인 에이전트
- **Herdr**: 여러 실제 터미널 세션, 워크스페이스, 워크트리와 에이전트 상태를 유지하고 제어하는 실행 감독층
- **OMP**: Claude·Codex·Qwen·GLM·로컬 모델 등을 역할별로 바꾸는 기본 코딩 실행기
- **Claude/Codex 네이티브 CLI**: 해당 제품 고유 기능이나 최고 품질이 필요할 때 쓰는 전문 실행기
- **Qwen Code**: 독립 교차검증 또는 Qwen 고유 동작 검증용 선택 실행기
- **직접 만들 부분**: 영속 작업 원장, 정책·계정 경계, 승인 큐, 지식베이스, 비용·품질 평가 기록, Herdr↔Hermes 연결 어댑터

즉, 제품의 핵심은 또 하나의 에이전트 셸이 아니라 **기존 에이전트들을 연결하는 작고 독립적인 관제 데이터 계층**이다.

## 확인된 로컬 상태

로컬 `herdr --version`은 `0.9.0`이다. `herdr agent start --kind`는 `omp`, `hermes`, `qwen`을 포함해 Claude, Codex, Gemini, OpenCode, Kimi 등 20여 종을 지원한다. `herdr integration status` 결과에서는 현재 Claude 통합만 `current (v9)`이고 OMP·Hermes·Qwen 통합은 설치되지 않았다. 세 실행 파일도 현재 PATH에서 발견되지 않았다.

따라서 **Herdr가 지원한다**는 사실과 **현재 이 Mac에서 실제 사용 가능하다**는 상태는 구분해야 한다. 설치 후에는 실제 상태 감지, 완료·차단 알림, 세션 복구를 각 도구별로 실증해야 한다.


### 1. Hermes를 상위 에이전트로 먼저 사용한다

Hermes는 Telegram·Discord·Slack·WhatsApp·Signal·이메일·Teams·브라우저 등에서 같은 게이트웨이를 제공한다. 지속 기억과 세션 검색, cron, 최대 동시 병렬 위임, 공급자 전환·fallback도 이미 제공한다. 그러므로 초기 모바일 앱이나 메시징 봇을 직접 만들 필요가 없다.

Hermes 내부 기억은 편의 캐시로 사용하고, 회사 정책·프로젝트 결정·업무 근거의 정본은 외부 Knowledge Base에 둔다. Hermes가 바뀌어도 지식과 작업 기록이 남아야 하기 때문이다.

### 2. OMP를 기본 코딩 실행기로 둔다

OMP는 역할별 `default`, `smol`, `slow`, `plan`, `advisor` 모델 라우팅과 세션 중 모델 교체를 제공한다. Claude·Codex OAuth, Qwen·GLM 계열 계획, OpenRouter, Ollama 등을 한 실행기에서 다룰 수 있다. 또한 AGENTS.md, CLAUDE.md, Cursor/Cline 규칙 등 기존 컨텍스트 형식을 읽고, 세션 로그에서 MEMORY.md와 skill을 생성하는 파이프라인도 갖는다.

따라서 모델 라우터와 프롬프트 기억기를 새로 만들기 전에 OMP를 시험한다. 단, 회사와 개인 계정은 별도 OS 사용자·컨테이너·프로필 및 자격증명 저장소로 분리하고 Control Core에는 비밀 값이 아니라 `account_profile_id`만 기록한다.

### 3. Qwen Code는 기본 셸이 아니라 선택 실행기로 둔다

Qwen Code도 여러 공급자와 로컬 호환 서버, MCP, hooks, 서브에이전트를 지원한다. 그러나 OMP와 겹치는 부분이 크다. 초기에는 다음 용도로만 유지하는 편이 단순하다.

- Qwen 모델의 도구 호출 품질을 Qwen 네이티브 셸에서 비교할 때
- OMP 결과에 독립적인 저비용 교차검증이 필요할 때
- Qwen hooks/ACP 호환성이 특정 저장소에서 더 유리할 때

무료 실행 경로로 Qwen Code 자체 OAuth를 전제하면 안 된다. 공식 문서상 해당 무료 티어는 종료됐다. 로컬 모델이나 시점별 무료 API 엔드포인트는 별도 공급자로 취급하고 가용성을 주기적으로 확인한다.

### 4. Herdr는 관제 UI이자 실행 버스이며 업무 정본은 아니다

Herdr는 여러 에이전트의 상태를 한 화면에 모으고 CLI로 prompt/wait를 자동화할 수 있다. 서버 재시작 후 원래 에이전트 세션을 복원하는 공식 통합도 있다. 이 기능은 이미 좋은 실행 버스다.

하지만 `agent prompt --wait`는 개별 작업 ID를 추적하지 않고, 이미 실행 중이던 turn의 완료가 wait를 만족시킬 수 있다는 공식 제약이 있다. 그러므로 완료 판정은 다음을 함께 확인해야 한다.

1. Control Core의 고유 `run_id`
2. 대상 worktree와 basis SHA
3. 실제 diff 및 산출물
4. 검사 결과와 근거
5. 에이전트 최종 상태

이 원장은 SQLite로 시작해도 충분하다. `tasks`, `runs`, `events`, `approvals`, `artifacts`, `knowledge_refs`, `account_profiles`, `evals` 정도면 된다.

## 직접 만들 최소 범위

### herdr-bridge

- Herdr snapshot/agent 상태를 읽어 `run.started`, `run.blocked`, `run.completed_candidate` 이벤트 생성
- 에이전트를 종류·모델·계정 프로필·worktree와 연결
- Hermes가 호출할 `submit_task`, `get_attention_queue`, `approve`, `get_run_evidence` 도구 제공
- 완료 후보를 diff·테스트·산출물 검사기로 확인한 뒤 `verified_complete`로 승격

### Knowledge Base

- 사람 정본: Markdown/Obsidian 호환 파일과 Git 이력
- 검색 파생물: SQLite FTS 또는 벡터 인덱스
- 분리: `personal`, `company`, `project`, `public` 네임스페이스
- 모든 검색 결과에 원문 경로, 버전, 수정 시각, 접근 범위 포함
- OMP/Hermes가 만든 기억은 제안 상태로 수집하고 자동으로 회사 정본에 승격하지 않음

### Prompt/Eval Loop

- 매 실행에서 요청, 라우팅 이유, 모델, 비용, 지연, 수정 횟수, 테스트, 사용자 교정 저장
- 야간 배치가 반복 실패와 비싼 작업 유형을 군집화
- GEPA류 최적화는 후보 프롬프트를 만들고 고정 평가셋에서 비교
- 통과한 후보만 사람이 승인해 repo harness 또는 개인 skill로 승격

## 추천 도입 순서

1. 별도 scratch 저장소에서 OMP·Hermes·Qwen Code와 Herdr 통합을 설치·검증한다.
2. 같은 작은 코딩 과제를 세 실행기로 돌려 규칙 로딩, 상태 감지, 세션 복구, 비용·품질을 비교한다.
3. Hermes를 개인 메신저 진입점으로 연결하고 Herdr 상태는 읽기 전용으로 전달한다.
4. SQLite Task Ledger와 `herdr-bridge`를 추가해 완료·차단·승인 이벤트를 정본화한다.
5. Obsidian 호환 KB와 검색 도구를 연결한다.
6. 실제 로그가 쌓인 뒤 라우팅 학습과 프롬프트 최적화를 붙인다.

초기 제품의 차별점은 “또 하나의 AI 에이전트”가 아니라 **Herdr가 관리하는 다양한 실제 에이전트와 Hermes 같은 개인 비서 사이에서 정책·증거·계정·지식을 휴대 가능하게 만드는 계층**이다.
