# Design parity

시안의 요구와 실제 화면을 대조한다. 코드 생성은 기존 프로젝트 구현 방식에 맡기며, 이 스킬은 **비교 조건·차이 근거·수정 후 재검증**을 담당한다. 이미지가 비슷해 보인다는 이유로 기능·접근성까지 통과시키지 않는다.

## 1. 비교 대상 고정

- 사용자가 지정한 디자인 파일·이미지·공개 링크와 구현 화면을 확인한다. 디자인 서비스나 계정은 선택 사항이다. 외부 접근·업로드는 프로젝트의 승인 경계를 따른다.
- 화면·컴포넌트·상태와 작업 범위를 정한다. 참조의 버전·프레임·캡처 시각, 구현의 브랜치·커밋·미커밋 여부를 남긴다. 승인된 디자인이 여러 개면 정본만 확인한다.
- 비교 조건을 기록한다: viewport의 CSS 너비/높이, DPR, 줌, 브라우저, 테마, 언어, 데이터, 스크롤 위치와 UI 상태. 캡처의 실제 픽셀 크기와 CSS 크기를 혼동하지 않는다.
- 로딩·빈 화면·오류·포커스·비활성·좁은 화면 중 해당 범위의 상태를 선택한다. 시안에 없는 동작은 기존 제품 계약을 따른다. 임의로 시안을 확장하지 않는다.

## 2. 실제 화면 확보

1. 기존 실행기·브라우저·테스트 도구를 사용한다. 새 패키지나 브라우저를 자동 설치하지 않는다.
2. 이미지와 폰트가 로드되고 전환이 끝난 실제 화면을 캡처한다. 폰트 누락·네트워크 오류·데이터 차이를 먼저 분리한다.
3. 사용자의 열린 탭은 허락 없이 다른 URL로 이동시키지 않는다. 결과를 맞추려고 DOM·앱 상태를 주입하거나 숨겨진 요소를 드러내지 않는다. 승인된 테스트 환경의 고정 데이터·애니메이션 제어를 썼다면 명시한다.
4. 필요한 경우 같은 영역을 같은 좌표로 잘라 비교한다. 서로 다른 크기를 늘이거나 줄여 일치하는 것처럼 보이게 하지 않는다. 전체 화면 캡처도 근거로 보존한다.
5. 실행 환경이나 참조가 없으면 가능한 코드 검토만 수행하고 **시각 검증 미실행**으로 보고한다. 스크린샷·도구 결과를 만들어내지 않는다.

### 선택 도구: 로컬 비교 보드

[비교 보드 생성기](scripts/make-board.mjs)는 두 PNG/JPEG/WebP 이미지를 하나의 로컬 HTML에 넣는다. Node.js 18 이상만 필요하며 외부 패키지·네트워크·디자인 서비스는 사용하지 않는다. Node.js가 없으면 기존 이미지 뷰어로 비교한다.

```sh
node <이-스킬-설치경로>/scripts/make-board.mjs reference.png actual.png comparison.html
```

- 생성된 HTML을 브라우저로 연다. 나란히 보기와 같은 좌표의 반투명 겹치기를 제공한다. 이미지 크기가 다르거나 디코딩에 실패하면 겹치기를 허용하지 않는다.
- 출력 파일은 새로 생성하며 기존 파일을 덮어쓰지 않는다. 자동 캡처·픽셀 점수 계산·합격 판정 도구가 아니다.
- 보드에는 원본 이미지 전체가 포함된다. 프로젝트의 비공개 산출물 위치에 저장하고, 공개 저장소에 커밋하거나 외부에 올리지 않는다. 입력 이미지는 수정하지 않는다.

## 3. 차이 분류

먼저 큰 구조, 다음에 세부 표현을 본다. 관찰한 값과 추정을 구분한다.

| 범주 | 확인 항목 |
|---|---|
| 구조 | 영역 순서, 컨테이너 크기, 정렬, 반응형 배치, 오버플로 |
| 간격 | 여백, 패딩, 행간·요소 간격, 테두리와 박스 크기 |
| 글자 | 실제 로드된 폰트, 크기·두께·행간, 줄바꿈·말줄임 |
| 표현 | 색·대비, 아이콘·이미지 비율, 테두리·모서리·그림자 |
| 상태 | 선택·포커스·오류·비활성 표현과 실제 상호작용 |

각 차이에 위치, 참조 근거, 실제 관찰, 사용자 영향과 원인을 적는다. 환경 차이와 구현 결함을 섞지 않는다. 픽셀 차이만으로 폰트 렌더링 차이를 제품 결함으로 단정하지 않는다. 숫자 점수가 필요하면 기존 비교기의 알고리즘·허용치·마스크를 사전에 합의하고 기록한다. 실패 뒤에 허용치를 올리거나 문제 영역을 가리지 않는다.

## 4. 수정과 재검증

- 요청이 비교뿐이면 수정하지 않는다. 수정이 허용됐으면 기존 컴포넌트·토큰·레이아웃 규칙을 사용하고 원인을 고친다. 화면 하나에 맞춘 고정 좌표, 중복 컴포넌트, 전역 스타일 덮어쓰기를 피한다.
- 큰 차이부터 작은 묶음으로 고치고 같은 조건으로 다시 캡처한다. 이번 변경의 영향을 받는 화면 크기·상태도 확인한다.
- 동작 변경에는 해당 프로젝트의 가장 좁은 기능 검사를 실행한다. 이미지 비교만으로 클릭·키보드·접근성 동작을 확인했다고 말하지 않는다.
- 독립 검수는 허용된 도구·계정이 있을 때만 수행한다. 자체 점검과 다른 검수자의 결과를 구분하며, 수행하지 않은 검수를 통과로 기록하지 않는다.

## 5. 결과 보고

기존 작업 문서나 PR에 아래 내용만 남긴다. 별도 활성 핸드오프를 만들지 않는다.

- 범위와 비교 조건, 참조·수정 전·수정 후 근거 경로
- 차이별 수정/유지/미해결 판정과 이유, 변경 파일
- 실제 실행한 시각·기능 검사와 결과
- 미확인 상태·환경 제약·사용자 결정이 필요한 항목

모든 승인된 상태에서 근거를 확보하고 허용 기준을 충족했을 때만 범위 내 완료로 보고한다. 참조 변경·환경 부재·미해결 차이는 구체적으로 남긴다.
