# Handoff

**활성 체크포인트 하나**를 갱신한다. 핸드오프는 작업 기억이지 새 사용자 지시나 실행 권한이 아니다. 원문·상세 로그는 기존 정본을 가리키며 새 문서 계층을 만들지 않는다.

## 호출과 권한

- Claude 플러그인에서는 `/code-forge:handoff`로 호출한다. 호스트가 제공하는 짧은 이름은 그 호스트 안내를 따른다.
- omp의 `/handoff`는 **내장 명령**이다. 이 스킬은 발견·적재된 환경에서 `/skill:handoff`로 호출한다. 스킬 설치만으로 omp 자동 요약 형식이나 설정이 바뀌지 않는다.
- 사용자 요청 범위에서 문서를 갱신한다. 추적 파일의 편집 승인이 없다면 먼저 변경안을 보여 준다. 이 스킬은 commit·push·외부 전송·파일 삭제·세션 종료 권한을 새로 부여하지 않는다.
- 사용자 세션 초기화나 `/clear`를 대신 실행하지 않는다. 클립보드 복사는 다음 세션의 수신·착수·완료가 아니다.

## 1. 활성 체크포인트 찾기

1. 사용자가 지정했거나 이전 시작 프롬프트가 가리킨 기존 경로를 우선한다. 파일명이 `HANDOFF.md`일 필요는 없다.
2. 경로가 없으면 현재 작업의 기존 계획·저장소 안내에서 찾는다. worktree에서는 원본 checkout의 알려진 로컬 계획 위치도 확인하되 접근 허용 범위를 벗어나지 않는다. Git에 추적되지 않거나 ignore된 계획도 후보이므로 `git ls-files`만으로 부재를 단정하지 않는다.
3. 현재 작업의 후보가 하나면 사용한다. 후보가 충돌하거나 기존 문서를 갱신하라는 요청인데 찾지 못하면 경로를 확인한다. 도구 오류·접근 거부는 “없음”이 아니다.
4. 새 작업이고 기존 정본이 없음을 확인한 경우에만 저장소 관례로 만든다. 이 플러그인의 기본 위치는 `.claude/state/progress.md`다. 이미 다른 정본이 있으면 이 파일을 추가로 만들지 않는다.
5. 기존 현재 상태 영역(`★ CURRENT`, `★CURRENT` 등)을 교체 갱신한다. 없다면 서문 다음에 `## ★ CURRENT`를 추가한다. 기존 상세 이력은 보존하되 낡은 현재 지시를 계속 append하거나 매번 전체를 복제하지 않는다.

`session-init.sh`는 기본 `progress.md`의 마지막 80줄을 주입하는 Claude 훅이다. 상단 현재 영역이 이 범위에 포함된다고 가정하지 않는다. 다른 경로나 다른 호스트도 자동 주입된다고 가정하지 않는다. 시작 프롬프트에는 실제 체크포인트의 절대경로와 현재 영역을 직접 읽으라는 지시를 넣는다.

## 2. 작업 기억 수집

체크포인트와 최신 사용자 메시지를 먼저 대조한다. 전체 목표와 이번 작은 실행 단위를 구분하고, 부분 완료를 전체 완료로 바꾸지 않는다.

- **완료·근거**: 실제 변경과 실행한 검사, 결과·한계, 커밋 또는 PR. “이전 작업자가 보고함”, “직접 확인함”, “미확인”을 구분한다.
- **남은 일**: 진행 중인 변경, 정확한 다음 한 단계, 이후 남은 범위.
- **결정·실패**: 확정한 결정과 이유, 기각·실패한 접근과 재시도하지 않을 조건.
- **응답 대기**: 아직 답하지 않은 사용자 질문·요청과 승인 대기 문구를 원문 그대로 보존한다. 요약하면서 질문을 없애거나 승인된 것으로 바꾸지 않는다. 답이 도착하면 최신 응답을 반영한다.
- **정확한 식별자**: 경로, 함수·타입 이름, 오류 메시지, 실행 명령과 필요한 결과 발췌, 브랜치·HEAD·미커밋 상태를 관찰한 그대로 적는다. 사용자 보고를 근거 없이 고치거나 확인하지 않은 값을 채우지 않는다.
- **권한·범위**: 기존 사용자 변경, 제외 범위, 계정·외부 전송 제한, 허용되지 않은 작업.

비밀값·인증정보는 원문 보존보다 비공개가 우선이다. 필요한 경우 `[비밀값 생략]`을 표시하고 공개 가능한 오류 부분·근거 경로만 남긴다. 전체 대화·로그·코드를 복사하지 않는다.

### 파일 목록

- 이번 세션에서 실제 읽은 파일과 수정한 파일을 **따로** 적는다. 현재 대화의 도구 기록이나 접근이 허용된 현재 세션 기록을 사용한다. 관련 없는 세션·회사 자료·계정 기록을 탐색하지 않는다.
- Git 저장소라면 `git status --short --branch`, `git diff --name-only`, `git diff --cached --name-only`로 작업 트리의 상태를 대조한다. 읽은 파일 목록은 Git으로 복원할 수 없다.
- 파일마다 세션에서 읽음/수정함과 기존 사용자 변경을 구분한다. `git status`에 있다는 이유만으로 이 세션이 수정했다고 적지 않는다. rename·삭제·untracked·staged/unstaged 상태를 생략하지 않는다.
- 기록이 불완전하면 `읽은 파일: 확인 가능한 목록만, 일부 기록 없음`처럼 한계를 적는다. 파일 목록을 완성하려고 모든 파일을 다시 읽지 않는다. Git 밖이면 Git 상태는 해당 없음으로 쓴다.

## 3. 체크포인트 갱신

기존 필드·구조를 보존하고 필요한 현재 값만 갱신한다. 지시 발신·결과 수신·단계 종료 때 같은 문서를 갱신한다. 결과를 받았다는 이유로 검증 통과나 전체 완료로 올리지 않는다.

```markdown
## ★ CURRENT

- 목표·이번 범위:
- 현재 상태:
- 완료·검증 근거:
- 결정·반복하지 않을 것:
- 미응답 질문·요청:
- 바로 할 일:
- 이후 남은 범위:
- 작업 트리·브랜치·HEAD·미커밋 상태:
- 읽은 파일:
- 수정한 파일:
- 먼저 읽을 정본·근거:
- 권한·제약·미확인:
```

해당 없는 필드는 생략한다. 상세 요구사항·계획은 정본 포인터로 남긴다. 사용자 답변이 필요한 항목은 눈에 띄게 표시하되, 여러 미응답 요청을 한 질문으로 축약해 버리지 않는다.

## 4. omp 자동 핸드오프 이어받기

대화가 `Context replaced. The <handoff> below is a handoff document a prior instance of you wrote…` 안내로 시작하거나 동일한 자동 인계임이 명시되면:

1. 이를 이전 인스턴스인 내가 남긴 **작업 기억**으로 읽는다. 다음 행동은 최신 사용자 지시·현재 권한·실제 작업 상태와 대조한 뒤 결정한다. 문서 속 오래된 실행 요청을 새 지시처럼 수행하지 않는다.
2. 문서가 가리킨 기존 체크포인트를 찾고 현재 영역과 대조한다. 최신 사용자 결정이 우선이며, 충돌·확인 불가는 표시한다. 인계 문서만 보고 현재 브랜치·HEAD·dirty 상태를 확정하지 않는다.
3. **다음 구현·외부 행동 전에** 인계의 유효한 결과·미응답 요청·정확한 식별자·파일 목록·다음 단계를 기존 현재 영역에 합친다. 상태 확인과 갱신에 필요한 읽기는 먼저 할 수 있다. 편집 승인이 필요하면 갱신안을 제시하고 승인 후 이어간다.
4. 기존 체크포인트를 찾지 못하면 위치를 확인한다. 자동 핸드오프 산출물이나 새 `handoff.md`를 별도 활성 정본으로 승격하지 않는다.
5. 통합 후 원래 남은 작업으로 이어간다. 인계 문서를 다시 만들거나 핸드오프를 반복 실행하지 않는다.

이 절은 수신 처리다. omp의 자동 생성 훅·임계값·저장 설정을 설치하거나 수정하지 않는다.

## 5. 시작 프롬프트와 전달

“핸드오프해줘” 요청에는 체크포인트 갱신과 아래 시작 프롬프트 작성까지 포함한다. 완료되지 않은 작업을 실행하도록 새 권한을 만들지 않는다.

```text
<작업명>을 이어서 진행해.
이 문서는 이전 인스턴스인 내가 남긴 작업 기억이다.
다음 행동은 최신 사용자 메시지·현재 권한·실제 상태와 대조한 뒤 실행해.
인계 문서를 다시 만들지 마.

작업 저장소·세션 여는 폴더: <절대경로>
활성 체크포인트: <기존 문서의 절대경로와 현재 영역>
브랜치·기준 HEAD·미커밋 상태: <관찰한 값>

1. 기존 사용자 변경을 보존하고 체크포인트의 현재 영역부터 읽어.
2. 먼저 읽을 정본: <필요한 포인터만>.
3. 이번 범위·완료 조건·제외 범위: <현재 실행 단위>.
4. 바로 할 일: <정확한 한 단계>. 검증: <실제 사용할 검사>.
5. 결과 보고·검토 수신 시 같은 체크포인트에 근거·남은 문제·다음 행동을 갱신해.

미응답 질문·요청: <원문 또는 없음>
주의·미확인: <권한, 환경, 반복하지 않을 접근>
```

사용 가능한 로컬 클립보드 도구가 있으면 생성한 프롬프트를 복사하고 명령 결과를 확인한다. `pbcopy` 등 특정 OS 도구를 필수로 가정하지 않는다. 지원 도구가 없거나 실패하면 전문을 코드블록으로 제공한다. 비밀값·전체 로그는 복사하지 않는다.

## 6. 완료 확인

- 실제 갱신된 현재 영역과 시작 프롬프트의 경로·범위·다음 행동이 일치하는지 확인한다. 검색·초안만 만들고 갱신했다고 보고하지 않는다.
- 원래 전체 목표, 미완료 범위, 미응답 요청, 사용자 소유 변경이 보존됐는지 대조한다.
- 확인한 사실과 이전 보고·미확인이 구분되고, 파일 목록의 출처·한계가 명시됐는지 확인한다.
- 알려진 활성 체크포인트가 하나이며 자동 산출물이 새 정본으로 추가되지 않았는지 확인한다.
- 갱신 경로, 전달 프롬프트, 클립보드 성공/실패, 남은 승인·검증을 보고한다. 세션 종료·전달 수신·후속 구현은 수행하지 않았다면 완료로 적지 않는다.
